GEAMS PILOT DEPLOY CHECKLIST  (set these on your host, then restart the server)

A. MUST SET BEFORE ANY REAL USE
 1. GEAMS_HQ_ADMIN_PASSWORD   a long passphrase. This is the HQ owner login ("hqadmin" unless GEAMS_HQ_ADMIN_USER is set).
 2. GEAMS_DATABASE_URL        postgres://user:pass@host:5432/db   (run: npm install pg)
                              or sqlite:/persistent/path/geams.db (Node 22.5+; the file must be on a disk that survives restarts)
                              Without it, data lives only on the server's disk and is lost if the host resets it.
 3. GEAMS_BACKUP_PASSPHRASE   turns on encrypted backups (the signing key is only included in encrypted backups).
 4. GEAMS_BACKUP_HOURS        e.g. 24 (0 = off).   GEAMS_BACKUP_KEEP  e.g. 14.
 5. GEAMS_BACKUP_PUT_URL (+ GEAMS_BACKUP_PUT_AUTH)   an off-site store that accepts HTTP PUT. Without it, backups sit on the same disk.
 6. Serve over https (phones need it for camera and GPS).
 7. Do NOT set GEAMS_SEED_DEFAULT_STATIONS in production (it creates demo passphrases). Issue real station logins from HQ.

B. STRONGLY RECOMMENDED
 8. GEAMS_TOKEN_SECRET        a fixed random secret so sign-ins survive a restart (otherwise the generated key file is used: back it up).
 9. GEAMS_REQUIRE_COMMANDER_ACCOUNTS=1   control rooms need a named commander account (HQ creates them).
10. GEAMS_REQUIRE_VERIFIED_CIVILIANS=1   only once SMS works (see 11). Until then civilian identities are self-declared.
11. GEAMS_SMS_URL / _METHOD / _BODY / GEAMS_SMS_API_KEY / _HEADER, GEAMS_SMS_INBOUND_KEY   phone codes and text-in alerts.
12. GEAMS_DATABASE_SSL=1      if your PostgreSQL host requires SSL.
13. GEAMS_VAPID_PUBLIC / GEAMS_VAPID_PRIVATE / GEAMS_VAPID_SUBJECT   fixed push keys (otherwise generated and stored).

C. OPTIONAL
    GHANAPOST_LOOKUP_URL / _METHOD / GHANAPOST_API_KEY / _HEADER   Ghana Post GPS lookup (needs your agreement with them)
    GEAMS_TSA_URL / GEAMS_TSA_CA   outside timestamp on evidence seals
    GEAMS_AUTO_APPROVE_UNITS (leave OFF: control rooms should approve crews)
    GEAMS_DB_MAX_FILE_MB (default 64), GEAMS_DATA / GEAMS_BLOBS / GEAMS_BACKUP_DIR (paths)

D. FIRST RUN
 1. Start the server. Sign in as HQ. Open "Security Configuration Check": every red line is something from A or B still missing.
 2. HQ: add stations, issue each control room's login, create commander accounts.
 3. Run a backup from HQ, then:  node geams-persist.js verify <backup file>
 4. Practise recovery once on a spare copy:  node geams-persist.js restore <backup file>  (server stopped)
 5. Try Lockdown and Rotate Tokens once, so nobody meets them for the first time in an emergency.
 6. Keep: your passphrases, GEAMS_BACKUP_PASSPHRASE and the database login somewhere safe and separate from the server.

E. MAPS (if maps look grey or missing)
 1. Deploy the whole "vendor" folder next to the HTML files (vendor/leaflet, vendor/geams-map.js, vendor/face, vendor/fonts). Without vendor/leaflet there is no map at all.
 2. Map pictures come from ArcGIS (server.arcgisonline.com) and the road map from OpenStreetMap. The phone or computer needs internet access to them. When they cannot load, a note says so: "Map pictures cannot be loaded right now". Pins, positions and routes still work.
 3. To avoid depending on outside servers, set GEAMS_TILE_URL (and GEAMS_TILE_ATTRIBUTION), GEAMS_ROUTE_URL, GEAMS_GEOCODE_URL to your own services. The apps read them from /config.js.
 4. Serve over https. After updating geams-sw.js, reload the app twice so phones pick up the new service worker.
 5. HQ's national map starts as the stylised map. Tap "Satellite" to see the real map.
 6. Quick test for a grey map: on the same device, open
    https://server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/7/63/63
    A small satellite picture means the device can reach the map servers. An error or blank page means the network (firewall, data plan, DNS) blocks them: use GEAMS_TILE_URL with your own tile server.
 7. The map now tries plain OpenStreetMap automatically when the satellite pictures cannot load, and shows a note when neither loads within 12 seconds.
 8. Grey map although the test link above shows a picture: Esri's satellite pictures stop at a fixed detail level, lower in many parts of Ghana, and past it the server sends plain grey tiles. The maps now stop at detail level 16 and stretch that picture instead. If it is still grey, set GEAMS_TILE_MAX_NATIVE_ZOOM=15 (or 14) on the server and reload. Zooming out with the minus button should show imagery again.

F. PASSWORDS AND RECOVERY (new)
 1. Tell control rooms: crew password resets are done from Officers > "Crew accounts at this station". Confirm the person's identity first.
 2. Tell civilians to make and store their recovery code (Profile > Recovery Code). Without it a lost phone means re-registering.
 3. Run one reset and one phone restore yourself before the pilot.

G. PRIVACY, RETENTION AND LOAD (new)
 1. GEAMS_PRIVACY_CONTACT (and optionally GEAMS_PRIVACY_URL): who a civilian contacts about their data. Shown in the privacy notice. If unset, the notice says so honestly. A lawyer must approve the notice wording and the lawful basis for face data.
 2. Face ID is now OPTIONAL and needs its own consent. The server refuses a face record sent without consent. GEAMS_REQUIRE_FACE_CONSENT=0 turns the check off (not recommended).
 3. Retention: GEAMS_ANON_INCIDENT_DAYS, GEAMS_RETAIN_INCIDENT_DAYS, GEAMS_RETAIN_FACEAUDIT_DAYS (0 = keep forever). GEAMS_RETENTION_AUTO=1 runs it daily. Use HQ > Data retention to preview first. Backups keep old data until they rotate out (GEAMS_BACKUP_KEEP).
 4. Many phones behind one mobile-network address: raise GEAMS_CIV_SESSION_LIMIT (default 120 new civilian sessions per address per 10 minutes).
 5. Load test: node t_load.js (about 2 min). Bigger: CIV=1000 CREWS=200 DURATION=3600 node t_load.js. Result on the build machine, 1,200 simulated devices: about 700 requests/s, reads 5 ms (p95), CPU 28%, no errors. Your hosting will be different: run it there.
 6. Print docs/pilot-runbook.html and docs/quick-start-cards.html. Do the real-phone test script (section 5 of the runbook) before launch.

H. FEEDBACK, DRILLS, OFFLINE QUEUE, SECURITY, LANGUAGES (new)
 1. Feedback: every app has a feedback button; HQ reads it under "Feedback from users". Civilian feedback is anonymous unless they tick "contact me".
 2. Drills: control room > "Drill" button. Incidents are marked [DRILL], left out of analytics and exports (add &drill=1 to the export address to include them).
 3. Crew offline queue: officer, fire and ambulance updates made with no signal are kept on the phone and sent later. Response-time analytics record the time the server received an update.
 4. Security: GEAMS_ALLOWED_ORIGIN (your site address), GEAMS_CIV_ALERTS_PER_HOUR (default 10 alerts per phone per hour). Security headers are now sent automatically. Give docs/security-review.html and tests/t_security.js to your security reviewer. A real independent test is still needed.
 5. The "Simulate Location" button is now hidden from civilians. Set GEAMS_ALLOW_SIMULATED_LOCATION=1 only on a test server.
 6. Languages: Twi and Hausa drafts (vendor/lang/*.json). They MUST be checked by native speakers before use: send docs/translation-sheet.csv. Ewe and Ga are SMALL unchecked drafts (about 22 and 8 phrases). Dagbani is empty and shows "not available yet". No code change is needed to correct or add a translation.

I. PILOT-SUPPORT FEATURES (new)
 1. App errors: apps report their own crashes to HQ (HQ > "App errors"). Anyone can send a report (limited to 30 per 10 minutes per address, 5 per page load); only HQ can read them.
 2. App version: every page is served with a version fingerprint. When you replace the files, open apps show "A newer version of GEAMS is ready - Update now". Send the version shown in HQ > App errors when asking for help.
 3. Staff action log (HQ > "Staff action log"): who changed or assigned what, lockdowns, token rotations, password resets, approvals. No names, phones or places are logged. The last 3,000 entries are kept.
 4. Duplicate alerts: control rooms get a warning when two open alerts from different callers are within 300 m and 20 minutes. A person decides whether to merge.
 5. False alarms & abuse (HQ): FLAG = alerts still arrive marked "verify by phone first"; BLOCK = alerts from that phone are refused and the sender is told to call 112. Use block rarely: it can stop a real emergency. A person with a new phone can start afresh; this is not foolproof.
 6. Restore by phone number: needs SMS set up (GEAMS_SMS_URL etc., see section C/D). Anyone who controls the registered SIM can restore the account, so tell people to protect their SIM. SMS has NOT been tested against a real gateway, only a local stand-in.

J. CONTENT-SECURITY-POLICY AND LIBRARIES (new)
 1. Every app page is now sent with a Content-Security-Policy. It blocks outside scripts and sending data to other sites. If you use your own tile, route or search servers (GEAMS_TILE_URL, GEAMS_ROUTE_URL, GEAMS_GEOCODE_URL) they are allowed automatically. Any other outside host the apps must reach: GEAMS_CSP_EXTRA_HOSTS="https://host1 https://host2".
 2. GEAMS_CSP=report only logs (to HQ > App errors) without blocking: use it if something unexpectedly stops working. GEAMS_CSP=off disables it.
 3. The policy still allows inline scripts (the apps need them), so it does not stop injected inline script. See docs/security-review.html.
 4. vendor/CHECKSUMS.txt and tests/t_vendor.js verify the bundled libraries. Re-run the library security check (see vendor/NOTICE.txt) before launch and every few months. face-api.js is no longer maintained.

K. ACCESSIBILITY, HANDOVER, ROSTER, LANGUAGES, TRAINING (new)
 1. Display settings: an "Aa" button on every staff page (bottom-right on large screens), and Profile > "Text size, contrast & movement" in the civilian app. Text size (normal/large/largest), higher contrast, reduce movement (follows the phone's own setting by default) and language. Saved on that device only. Larger text uses the browser's page zoom, so it works best on current Chrome, Edge and Safari. Higher contrast darkens and sharpens colours; it does not redesign the screens and has NOT been checked against WCAG with a real screen reader. Test with TalkBack/VoiceOver on a real phone before you claim accessibility.
 2. Screen-reader support that is always on: icon-only buttons get names, clickable boxes can be reached and pressed from a keyboard, pop-up messages are announced. Anything the apps build later without an obvious label may still be missed.
 3. Shift handover: Station > Shift Handover now files a record on the server that cannot be edited or deleted. The next commander sees "Handover notes are waiting" and confirms they read it (time and who are kept). If the phone has no signal it says "not saved" and command does NOT change. Only that control room and HQ can read the notes. Notes are free text: tell commanders not to put victims' personal details in them.
 4. Crew roster: Station > Crew Roster. The commander adds registered crew (officers, fire, ambulance) and sets day/night/off shift. Each crew member sets their own Available / On break / Unavailable from "My availability" (the clock button in the fire and ambulance apps, a button on the Profile page in the dispatch app). It is what people DECLARE, not a live location, and it does not stop alerts reaching them. Only officers show "live" (signed in now).
 5. Staff languages: the same language picker works in all staff apps, but only a handful of button and menu words are translated (Twi and Hausa drafts for "Password" and "Settings"). Incident details, types, statuses and names are never translated, on purpose. docs/translation-sheet-staff.csv lists the 300+ screen words that still need a native translator. When it comes back filled in, run: node make-lang.js docs/translation-sheet-staff.csv staff-   (and for the civilian list: node make-lang.js docs/translation-sheet.csv). Add --checked only after a native speaker has verified that column. Words that appear only in pop-ups and messages built in code are not on the sheet yet.
 6. Guided tour: Aa > "Take the guided tour" in every app. It highlights the real buttons and explains them, and sends nothing. For hands-on practice use the control room Drill button. The tour text is written in English only and was written by us, not by trained instructors: have a real commander read it and correct anything that does not match your procedures.
 7. Fixed: the station top bar showed a fixed "2 CRITICAL" even with no incidents. It now shows the real count.

L. PILOT READINESS ROUND (new)
 1. Unanswered-alert warnings: an alert that waits too long (GEAMS_ESCALATE_SECS, default 120 s; 45 s if that control room has no screen open) shows HQ a banner and shows the nearest other control rooms a notice with phone numbers. GEAMS only WARNS: nothing is moved or sent on by itself. A person at HQ or the neighbouring control room must phone and act. "Online" means the control room's screen is open and polling the server. Needs people watching HQ during the pilot.
 2. Pilot strip and pause switch: civilians see "<GEAMS_PILOT_LABEL> - GEAMS is being tested. In an emergency you can also call 112." HQ owner > "Pause / resume civilian alerts" stops new alerts and turns the strip red with your message (always includes 112). Use it if control rooms cannot answer.
 3. Honest sending: the civilian app says "ALERT SENT" only after the server accepted it. With no signal it saves the alert, says plainly it has NOT reached the control room, offers Call 112 / text, and sends when signal returns. If the server refuses (blocked sender, paused) it shows a red "NOT accepted - call 112" box and does not retry forever. Incident numbers are now 6 random characters (4-digit numbers collided and were silently dropped).
 4. Server saving: a failed save (disk full) is no longer silent: HQ shows "SERVER CANNOT SAVE", the log shows !! SAVE FAILED, saving retries every 5 s. A damaged data file is kept (d.json.corrupt-...), recovered from the last complete copy where possible, and HQ is told. Up to ~0.5 s of the newest changes can be lost if the server is killed. Restore drill: t_restore.js; command in deploy/DEPLOY.md section 5.
 5. Deployment kit: deploy/ (env template, Caddy, nginx, systemd, install.sh, DEPLOY.md). The server now listens only on this machine when GEAMS_BIND=127.0.0.1 and trusts X-Forwarded-For only from this machine (so rate limits cannot be dodged by a faked address). NOT machine-checked here: the Caddy and nginx files and install.sh run as a whole on a clean server. Try it on a spare server first.
 6. Bulk setup: Station > "Add Crew in Bulk" (CSV paste/load, preview, create, printable login sheet with one-time passwords; people must change them at first sign-in). HQ owner > "Add control rooms in bulk" (station ID + one-time passphrase). Passwords are shown once.
 7. Pilot report: HQ > "Pilot report": anonymised counts, speeds, reliability, feedback totals, and a plain list of what it cannot tell you. Print or download JSON.
 8. CSP: 'unsafe-eval' is removed (the face library was shown to run without it in a desktop browser with software graphics; NOT tested on real phones). If a phone's face check stops working, set GEAMS_CSP_EVAL=1. 'unsafe-inline' stays: about 860 inline click handlers plus many built in code would all have to be rewritten, and doing that safely needs a full re-test of every button; it is deliberately deferred. Replacing face-api.js is also deferred: any replacement must be tested with real faces on real phones.
 9. Tests added: t_escal, t_escal_ui, t_civsend, t_restore, t_crash, t_soak (4 min here; run DURATION_MIN=1440 on your server for 24 h), t_deploy.sh, t_bulk, t_report.
10. 112 and no-signal routes (new): a phone cannot tell GEAMS that someone dialled 112. (a) In the civilian app the alert sheet now has "Call 112 and alert nearest control room": one tap sends the alert and opens the dialler. Dialling 112 by hand does NOT tell GEAMS: say so in the pilot briefing. (b) "Text GEAMS" appears in the no-signal box only when GEAMS_SMS_NUMBER is set; needs your SMS gateway to forward texts to /api/sms/inbound (GEAMS_SMS_INBOUND_KEY). (c) 112 hand-over: POST /api/e112/inbound with GEAMS_E112_KEY: for the 112 operator to forward each call (docs/e112-handover-spec.md). Needs an agreement with the 112 operator/telecoms. All three tested against local stand-ins only. Routing uses control rooms in the HQ registry (create them in HQ or by bulk import); the built-in demo stations are not used. Test: t_e112.js.
11. Final cross-check fixes: (a) on a real deployment (GEAMS_SEED_DEFAULT_STATIONS not set) the 13 built-in demo stations are hidden in the civilian, HQ, fire, ambulance, dispatch and station apps and cannot receive alerts; the server refuses an alert for an inactive control room and says call 112. Create real control rooms in HQ first, or no civilian alert can be filed. (b) "Simulate my location" is now "Set my area (no GPS)": no invented position, every such alert says AREA ONLY, NO GPS. (c) removed fake live-audio bars/AES-256 label in the HQ live view, random offsets for station approval and route preview, random quick replies, and a dead Download CSV button. Test: t_demooff.js.
12. Fire HQ and Ambulance HQ (new): stand-alone screens (geams-fire-hq.html, geams-ambulance-hq.html) for the two services, which report to their own HQ and not to Police. Create the accounts at HQ dashboard > "Fire & Ambulance HQ accounts". Control rooms still receive and forward every alert. Tests: t_agency.js, t_agency_ui.js. See GEAMS-README.txt for what they can and cannot do.
